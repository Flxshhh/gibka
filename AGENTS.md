# Контекст проекта «Листогиб»

При работе с проектом сверяй эту карту с кодом. Она фиксирует архитектуру и модель расчёта, изученные на коммите `ed249bb`.

По просьбе владельца проекта после проверки готовых изменений приложения обновляй версию веб-ресурсов, создавай коммит и отправляй его в `origin/main` для публикации на GitHub Pages. Если пользователь отдельно попросил оставить изменения локально, следуй этому указанию.

## Крепления в 2D

- Контрольная точка «ДО» для задачи о креплениях — коммит `0ef441df1c55deccd74101024285625dfebc8af2`. По команде «верни ДО» отмени опубликованные изменения этой задачи и опубликуй откат в `origin/main`.
- «Держатель пуансона.doc» задаёт постоянный держатель H100, L150, Z7 мм с гнездом 13 мм. В 2D держатель фиксирован относительно посадочной плоскости пуансона, а при перевороте зеркалится. Только для матриц с двумя и более ручьями и подходящим нижним вырезом применяется отдельный WPM 60 с профилем из DWG (60 × 20 мм, выступ 15 × 5 мм со смещением 9,5 мм от края). Все остальные матрицы опираются непосредственно на обычную подложку. WPM 60 вставляется в обычную подложку, которая опирается на стол. При смене ручья переходник позиционируется относительно нижнего паза матрицы. 3D крепления пуансона согласовывается после 2D.

## Архитектура

- Статическое русскоязычное приложение для листогибочного пресса. Точка входа `index.html`, стили в `css/style.css`. Сервер и сборка для веб-версии не нужны. Обычные скрипты загружаются в порядке из HTML и публикуют объекты в `window.LG`.
- `data.js` содержит таблицу усилий, материалы, коэффициенты минимальной полки, станок и пустую деталь по умолчанию. `catalog*.js` добавляют параметрический и DXF-инструмент в `LG.CATALOG`. Каталог только для чтения, «+ Копия» создаёт редактируемый экземпляр в «Моих». Идентификаторы каталога используются в сохранённых деталях и ссылках.
- `ui.js` связывает вкладки «Деталь», «Гибка», каталоги инструмента и таблицу усилий. `ST` держит состояние, `resolve()` подбирает инструмент и вызывает `C.analyze()`, `buildPlan()` собирает контекст `LG.Sim` и кэширует план по детали, инструменту, станку, Ri и K. При ударах интерфейс порциями проверяет другие пуансоны и затем матрицы.
- Состояние хранится в `localStorage` под префиксом `lg.v1.`. JSON-резервная копия содержит личный инструмент, станок и сохранённые детали. Ссылка «только гибка» кодирует деталь и контекст в `#g=` и открывает симуляцию без записи в хранилище. Миграции старых параметров пуансонов находятся в начале `ui.js`.
- Веб-версия публикуется через GitHub Pages. `bump-version.sh` синхронизирует метки ресурсов в HTML и `version.txt`. Android — Java WebView с локальной копией сайта из `assets/www`. Ручной workflow `.github/workflows/android.yml` собирает APK и скачивает three.js в локальные ресурсы.

## Интерфейс и представления

- Визуальная система WIRKEN использует холодный серый фон, белые панели и синий акцент. Цвета и состояния заданы CSS-переменными, есть тёмная тема и адаптивные сетки. Линейные иконки берутся из SVG-спрайта в HTML. Чертёжная сетка, размерные линии и координаты сосредоточены внутри чертежей.
- `svg.js` переводит координаты модели с осью Y вверх в экранные координаты SVG, строит пути, размеры и область просмотра. `view3d.js` экструдирует те же сечения вдоль длины гиба; веб-версия загружает three.js r128 по запросу. Геометрия листа и инструмента общая для 2D и 3D. Плеер, карта гибки для печати и запись видео находятся в `ui.js`.
- Профиль задаётся массивом `part.segs` из `{dir, len}`. В режиме «С углом» кнопки выбирают абсолютное направление по кругу. В строке `30 90 60 -90 30` числа чередуют длину и знаковый внутренний угол, а парсер переводит угол в приращение направления. Знак задаёт сторону поворота. Режимы размеров `outer`, `inner`, `mid` задают разные плоскости виртуальных острых вершин.

## Расчёт, геометрия и физическая модель

- Координаты сечения в мм. X направлен вправо к заднему упору, Y вверх. Положительный поворот против часовой стрелки. `beta = norm180(dir[i+1] - dir[i])`, внутренний угол `180 - abs(beta)`. Стороны A и B находятся слева и справа по ходу профиля.
- `calc.js` берёт ближайшую строку таблицы по толщине S. Автоподбор использует средний доступный V этой строки и ищет подходящую каталожную матрицу, при отсутствии кандидата строит условную. B и Ri интерполируются по V. Радиус гиба по умолчанию берётся как максимум табличного Ri с поправкой на материал и радиуса пуансона. K вычисляется по формуле в `C.kFactor()` с ограничением 0,2–0,5. Ri и K имеют ручные переопределения.
- Усилие в кН/м берётся из таблицы с пересчётом пропорционально S² или по формуле `1.42 * 420 * S² / V` с коэффициентом материала. Для полного усилия умножается на длину гиба в метрах. Перевод в тонны силы делением на 9,81. B для 90° корректируется по внутреннему углу, сравнивается с меньшей наружной полкой у гиба.
- `C.analyze()` переводит размеры к средней линии через поправку `(S/2) * tan(abs(beta)/2)`, затем вычитает отступы к касательным `(Ri + S/2) * tan(abs(beta)/2)`. Тангенсы используют угол в радианах. Длина дуги развёртки по нейтральному слою равна `abs(betaRad) * (Ri + K*S)`. Развёртка складывается из прямых участков и этих дуг. Каждая линия гиба отмечена на середине дуги.
- `G.sheetShape()` строит геометрию по средней линии. Сохраняет длину дуги `abs(betaRad) * (Ri + S/2)`, меняя радиус обратно пропорционально углу текущей фазы. Плоское состояние использует малый ненулевой угол для численной устойчивости. Смещение на ±S/2 по нормали даёт обе поверхности листа. `Sim.finish()` корректирует упор на разницу нейтральной и средней линий для ещё не выполненных гибов.
- `geom.js` строит контуры параметрических пуансонов и матриц, работает и с готовыми DXF-полигонами. Носик пуансона расположен в локальном `(0,0)`, ось рабочего ручья матрицы лежит на `x=0`. У матрицы отдельно учитываются плечи, их радиус и положение верхней плоскости. `Sim.place()` ориентирует внутреннюю сторону текущего гиба вверх, совмещает ось с ручьём и ставит лист по касанию наружной поверхности с плечами. Зеркальность установки детали и зеркальность пуансона — отдельные параметры.
- `Sim.checkStep()` проверяет пять фаз от 0 до 1. Столкновения ищутся по строгим пересечениям рёбер сечения листа с инструментом и деталями станка. В окрестностях носика и плеч предусмотрены допуски для рабочих контактов. Касания концами и полное вложение полигонов без пересечения рёбер такой алгоритм не обнаруживает. Симуляция — кинематическая модель поперечного сечения с дискретными проверками; она не моделирует напряжения, пружинение или контакты по длине в 3D.
- Автопорядок — ограниченный DFS с предпочтением крайних гибов и текущей ориентации. Кэш зависит от множества выполненных гибов, текущего гиба и зеркальности. При неудаче строится жадный план с минимальным числом найденных ударов на каждом шаге. Ручной порядок перебирает ориентации для заданной последовательности. Шаг хранит сторону A/B вверх, край к заднему упору и подсказки по перевороту.

## Импорт DXF

- `dxf.js` разбирает текстовый DXF в браузере. Линии, дуги, окружности, полилинии с bulge и вставки блоков преобразуются в сегменты. Дуги дискретизируются, контуры инструмента упрощаются с допуском. Основной контур выбирается по замкнутости, площади и ожидаемым габаритам. Масштаб инструмента 1:1 в миллиметрах.
- При импорте пуансона алгоритм ищет носик и хвостовик и нормализует ориентацию. Для матрицы распознаёт рабочие ручьи на разных гранях и центрирует каждый рабочий вариант относительно его оси. Для детали открытая ломаная задаёт профиль, замкнутый контур распознаётся по двум торцам и парным сторонам, из которых восстанавливаются толщина и средняя линия.

## Проверка при изучении

- На профиле `30 90 60 -90 30` из стали толщиной 1,2 мм с штатным пуансоном и условной матрицей V10 расчёт дал Ri = 1,3 мм, K ≈ 0,33369 и развёртку ≈ 115,342 мм. Исполнение расчётных JS-модулей подтвердило знаки обоих гибов, конечность координат в пяти фазах первого гиба и план без зарегистрированных ударов. Браузерный интерфейс и APK при этой проверке не запускались.
